# Solutions

A durable record of things learned while building this app that took real
investigation to figure out -- so the next session (human or Claude) doesn't
have to rediscover them from scratch.

Not a changelog. Not a design doc. Write an entry when something surprised
you, took more than a couple of tool calls to root-cause, or has a gotcha a
future change could easily re-trip. Skip it for routine feature work --
BACKLOG.md and PR descriptions already cover that.

One file per topic, named for what it's about (`snapshot-picks-window.md`,
not `2026-09-11-fix.md` -- dates belong in git history). Keep entries short:
what the surprise was, why it happens, and what to do about it next time.
